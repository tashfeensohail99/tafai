- Organization: organizations, branches, departments, designations, employee_profiles, client_profiles, partner_profiles.

- Documents: document_requirements, documents, document_versions, document_verifications, ocr_results, missing_document_requests, document_expiry_alerts.

- Audit/timeline: audit_logs, activity_timeline_events, security_events, notifications.

ERD field rules:
- Every business table should include id, created_at, updated_at, deleted_at where soft delete is needed, created_by_user_id, updated_by_user_id where applicable.
- Ownership fields should exist where access is scoped, such as owner_employee_id, assigned_employee_id, department_id, client_id, partner_id, branch_id.
- Audit-sensitive tables should include status, status_changed_at, status_changed_by_user_id where applicable.
- Indexes required for phone/email duplicate checks, lead source/campaign filters, assigned employee queues, case status, document status, payment status, appointment date, audit event lookup, and timeline lookup.

**Required Revision 4 - Screen-Wise Acceptance Criteria**
The developer must create module-level acceptance checklists, not only weekly acceptance.

Minimum acceptance examples:
- Lead module: admin can create manual lead; website/test lead enters CRM; social/test lead enters CRM; duplicate phone/email is detected; lead source/campaign is saved; auto assignment works; admin can reassign with reason; employee sees assigned lead; audit log records assignment.
- Partner/referral module: partner can log in; partner can submit referral; referral is attributed to partner; admin can view and assign referral; partner sees limited status only; private client notes/documents are hidden.

- Appointment module: employee availability can be configured; appointment can be booked, rescheduled, canceled; reminder job runs; appointment appears on admin and employee calendars.
- Client portal: client can log in; client sees only own case; client uploads document; client sees missing document request; client sees appointment/payment status.
- Document module: officer sees queue; document can be previewed; OCR/classification runs or manual review is required; officer can verify/reject/request replacement; expiry/missing status is visible; audit records access and decision.
- Processing module: processing officer sees converted cases; case moves through configured stages; notes/proofs can be added; escalation works; timeline updates.
- Finance module: invoice can be created; payment can be recorded/verified; receipt can be generated/uploaded; installment/refund statuses work; finance report totals match test data.
- Reports module: daily operations, lead source, employee, appointment, revenue reports load; filters work; exports work; export is audited.
- AI module: AI job is queued; status changes from pending to processing to completed/failed; output is stored; employee reviews output; failures are retryable/logged.
- Flutter mobile: user logs in; dashboard loads; case status loads; document upload works; appointment notifications/push token works where provider ready; attendance check-in/out basic works.
