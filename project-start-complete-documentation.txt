## 7. Business Workflow Documentation

### 7.1 Lead Flow

Flow:
Lead source -> CRM entry -> duplicate check -> auto/manual assignment -> sales follow-up -> screening -> appointment -> document request -> conversion/rejection.

Detailed steps:
1. Lead enters from website, Facebook, Instagram, WhatsApp, manual entry, or partner referral.
2. CRM normalizes phone, email, name, country, service interest, source, and campaign.
3. System checks duplicates by phone, email, and fuzzy name match.
4. If duplicate is likely, lead goes to Duplicate Review.
5. If unique, assignment engine assigns by service, country, branch, workload, employee availability, and priority.
6. Sales receives notification.
7. Sales contacts lead through WhatsApp/call/manual note.
8. Sales completes screening.
9. Sales books appointment if needed.
10. Sales sends document request.
11. Lead is converted to client/case or rejected/closed.
12. Audit and timeline are updated.

Needed decisions:
- Final duplicate matching rules.
- Assignment rules.
- Hot/warm/cold definitions.
- Lead rejection reasons.
- Lead reopen rules.

### 7.2 Case Flow

Flow:
Sales converts lead -> case created -> documentation review -> processing department -> finance verification -> case status update -> closure.

Detailed steps:
1. Sales converts qualified lead.
2. System creates client profile and case.
3. Documentation receives task/checklist.
4. Client uploads documents via portal/mobile or staff uploads on behalf of client.
5. Documentation verifies documents.
6. Approved file set moves to Processing.
7. Processing updates case stage and proof attachments.
8. Finance verifies payment milestones where required.
9. Case status updates are shown to client where appropriate.
10. Case closes when final outcome/action is complete.

Needed decisions:
- Case stages by service/country.
- Which statuses client can see.
- Which handovers require finance check.
- Who can close/reopen cases.

### 7.3 Document Flow

Flow:
Client uploads/sends document -> system stores private file -> AI/OCR checks document -> documentation officer reviews -> verified/rejected/replacement requested -> client notified.

Detailed steps:
1. Document is uploaded through client portal/mobile/admin/employee.
2. File is stored privately in S3-compatible storage.
3. Metadata is saved in database.
4. OCR/classification job is queued.
5. AI/OCR extracts possible document type, expiry, and visible fields.
6. Low-confidence result is marked Manual Review Required.
7. Documentation officer reviews preview and AI/OCR result.
8. Officer verifies, rejects, or requests replacement.
9. Client is notified.
10. Timeline and audit log are updated.

Needed decisions:
- Which documents require expiry validation.
- Which documents can be uploaded by client.
- Which documents require staff-only upload.
- Who can delete/replace files.

### 7.4 Finance Flow

Flow:
Payment requested -> payment received -> finance verifies -> receipt/invoice generated -> installment/refund tracked -> case updated.

Detailed steps:
1. Finance/payment requirement is added to client/case.
2. Invoice is created if needed.
3. Client pays through approved method.
4. Finance records and verifies payment.
5. Receipt is generated/uploaded.
6. Installment or refund status is tracked if applicable.
7. Case/payment status is updated.
8. Reports and audit logs update.

Needed decisions:
- Who can create invoice.
- Who can verify payment.
- Who can reverse/correct payment.
- Required receipt/invoice format.

### 7.5 Client Portal Flow

Flow:
Client logs in -> sees case status -> uploads documents -> checks appointments -> sees payment status -> receives notifications.

Detailed steps:
1. Client receives portal invite.
2. Client logs in through password/OTP process.
3. Client dashboard shows case status, pending documents, appointments, payment status, notifications.
4. Client uploads documents.
5. Client receives replacement/missing document requests.
6. Client sees receipts/payment status.
7. Client receives appointment/case updates.

Needed decisions:

- Which case statuses are shown externally.
- Whether client can send messages from portal.
- Whether client can download documents/receipts.

### 7.6 Partner/Referral Flow

Flow:
Partner logs in -> submits referral -> admin/sales reviews lead -> partner sees limited status.

Detailed steps:
1. Admin creates partner account or partner is invited.
2. Partner submits referral form.
3. Referral enters CRM as lead with partner attribution.

## 8. High-Level Technical Architecture

Recommended architecture:
- Frontend: Next.js/React/TypeScript.
- Mobile: Flutter for Android and iOS.
- Backend: NestJS/Node.js modular monolith.
- AI worker: Python FastAPI.
- Database: PostgreSQL.
- Queue: Redis + BullMQ.
- File storage: S3-compatible private object storage.
- Auth: JWT/refresh token, HttpOnly cookie for web, secure storage for mobile.
- Deployment: Dockerized services with staging and production.

## 13. Security Model Draft

Authentication:
- Passwords hashed using Argon2id or bcrypt with strong cost factor.
- JWT access token with short expiry.
- Refresh token rotation.
- HttpOnly secure cookies for web where possible.
- Secure token storage for Flutter.
- Password reset token expiry.
- Optional MFA-ready design for admins.

Authorization:
- Server-side RBAC on every API.
- Ownership guards for client, partner, employee, department, branch, and assignment-scoped data.
- No frontend-only permission enforcement.

File/document security:
- Private object storage only.
- Signed URLs with short expiry.
- Permission check before URL generation.
- Document access audit log.
- No public document links.

Audit events:
- Login/logout.
- Failed login.
- User/role/permission changes.
- Lead assignment/reassignment.
- Status changes.
- Document upload/view/review/reject/replacement.
- Payment/invoice/receipt changes.
- Case handover/escalation.
- Report export.
- Integration webhook failure.
- Admin settings changes.

Data privacy:
- Collect only needed PII.
- Limit AI provider payloads where possible.
- Human review required for AI outputs.
- Data retention policy required.
- Document deletion/archival policy required.

Monitoring/legal-sensitive features:
- Call recording requires consent wording.
- Employee monitoring requires policy and consent.
- Device tracking requires device usage policy.
- Attendance checks require attendance policy.
- Face/GPS/liveness checks are not included unless separately approved.
