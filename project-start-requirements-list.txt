# Project Start Requirements List - Tashfeen AI Platform

Purpose: This document lists exactly what is needed from the client side before development starts properly. It also records initial design, shared component, architecture, and theme decisions so the team can begin with fewer assumptions.

Mandatory development instruction source:
- DEVELOPMENT_STANDARDS.md contains the official coding, architecture, security, UI component, theme, audit, RBAC, testing, and project-management rules.
- .github/copilot-instructions.md makes those standards available as project-level Copilot instructions for future coding work.

Commercial baseline:
- Final project development amount: CAD 10,500.
- Currency must stay CAD in all final project documents.
- Any old USD 8,000 references must be removed from the final agreement, payment schedule, annexures, proposal, and plan.

Theme baseline:
- The system must support both light theme and dark theme from day 1.
- Theme should be implemented through design tokens/CSS variables, not hard-coded colors.
- User preference should be saved per user profile where possible.
- System default can follow device/browser preference if user has not selected a theme.

## 10. Architecture Start Decisions

Recommended architecture:
- Web frontend: Next.js/React/TypeScript.
- Mobile: Flutter for Android and iOS.
- Backend: NestJS/Node.js modular monolith.
- AI worker: Python FastAPI.
- Database: PostgreSQL.
- ORM/query: Prisma, with raw SQL/views for heavy reports if required.
- Queue: Redis + BullMQ.
- Storage: S3-compatible private object storage.
- Auth: JWT/refresh token, HttpOnly cookies for web, secure token storage for mobile.
- Deployment: Dockerized services, staging and production environments.

Suggested high-level system flow:
Lead sources -> API/Webhooks -> Duplicate check -> Assignment engine -> Sales/WhatsApp -> Appointment -> Client portal/mobile -> Document upload -> Documentation review/OCR -> Processing -> Finance -> Case lifecycle -> Reports/Audit.

Suggested environments:
- Local development.
- Staging/UAT.
- Production.

Suggested domains/subdomains:
- admin.tashfeen-domain.com
- client.tashfeen-domain.com
- api.tashfeen-domain.com
- webhooks.tashfeen-domain.com if separated

Recommended UAT/sign-off process:
1. Developer deploys milestone to staging.
2. Client receives checklist and test accounts.
3. Client tests within agreed review window.
4. Bugs are logged with screen, role, steps, expected result, actual result, screenshot/video, sample record.
5. Fixes are deployed.
6. Client approves by email/WhatsApp/written milestone approval.
7. No feedback within agreed acceptance period means milestone is treated according to agreement acceptance terms.

Recommended change request process:
1. Request submitted in writing.
2. Team classifies as bug, clarification, small in-scope adjustment, or change request.
3. Change request gets cost/timeline/module/testing impact.
4. Client approves impact before work starts.
5. Approved change enters backlog.

## 14. Final Recommendation

Start the project only after the Week 1 client checklist is mostly complete. Development can begin with reasonable assumptions for logo, colors, UI components, ERD, and architecture, but external integrations and legal-sensitive modules depend on client-provided access, credentials, and policies. Dark and light theme support must be implemented from the first UI foundation, not added at the end.
